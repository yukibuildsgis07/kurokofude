# 黒子筆（Kurokofude）— AIに図面を渡す前の関所

## インパクト

道路台帳や河川台帳の図面には、地番の下に地権者の氏名が書かれています。AIに幾何補正を任せたくても、個人情報入りの画像は渡せません。現場ではペイントで1枚2分かけて塗り、斜めの文字では周りの線まで消えます。測量会社で情報システムを担当する私自身の不便です。黒子筆は氏名だけを手元のPCで塗り、地番は位置合わせの鍵として残します。自社の標準手順にし、同業者の会で紹介して、個人情報の壁でAIを使えずにいる小さな測量会社や自治体に届けます。

## デモ

図面1枚で地番と氏名の関係を見せてから、3つの場面を流します。①塗る前の図面を開こうとして、関所に止められる。②スキルが塗り、地番の一覧だけが返り、人が確認画面で確定する。③わざと約43mずらした図面が、地番だけの照合で約1.4mに戻る。

## Claudeの活用

「Claudeが生データを見ずに仕事をする」形を、機能の組み合わせで作りました。フックが塗る前の図面への直接アクセスを止め、MCPは塗った図面と地番の一覧だけを返します。スキルは人の確定を待つ手順を持ち、サブエージェントが公図との照合を担います。

開発では役割を分けました。私が方針を決め、Fableが設計し、Opusが実装します。CLAUDE.mdに規約を書き、Opusは判断に迷うとquestions.mdに書いて止まり、Fableと私が答えました。関所は開発の初日から効いていて、Opus自身も何度も止められました。その誤検知の記録から、止めた理由を伝える機能が生まれました。

## 深さと実行力

ダミー図面5枚で測り、測るたびにaccuracy_logに記録しました。氏名カバー率は61%から99.7%になりました。この伸びには、図面を実物に寄せた効果と指標の変更も含み、記録で区別しています。地番生存率99.68%は目標の100%に届いていないので、黒子筆は塗り漏れゼロを保証せず、人の確認を手順に含めます。現場の目視で見つかった塗り漏れは原因を突き止めて直し、Windowsでのインストールから塗りまでは、CIで毎回確かめています。氏名はすべて架空で、図面は法務省 登記所備付地図データ（G空間情報センター）を加工して作成しました。
